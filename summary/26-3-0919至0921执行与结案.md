### 一、`preflight` 的 cross-seed 探活：**确实是恒假，已修**

★ 上一轮我写的措辞是"**可能**长期恒假"，并说"要证它得先读 cross-seed 的路由"。

|---|---|
| `CrossSeedClient.ping()` 原实现 | `return response.ok`，而 `Response.ok` = **`200 <= status < 300`** |
| 实测应答 | 根路径 `GET http://cross-seed:2468` ⇒ **HTTP 404** |
| ⇒ 结论 | **恒判 False**，与 daemon 死活**完全无关** |

#### 三、★★★ **新问题（本轮回答）：每日摘要能不能靠 docker 驱动？** —— **不能**

> ★ 用户原问：「每日邮件能不能靠 docker 驱动，而不是自带的任务计划？」
> ⇒ **答：不能。** 且这不是"嫌麻烦"，是**一道硬边界**（`ERR-DOCKER-10` 已用**实物证据**验过）。

| 诉求 | 容器能否做到 | 判据 |
|---|---|---|
| **每天定时"到点"** | ✅ 能（容器内 cron/sleep 循环即可）| 通用容器能力 |
| **真正把信发出去** | ❌ **不能** | ★★ `ERR-DOCKER-10`：`docker exec … notify-spool.sh --test-mail` ⇒ **读不到 `/etc/ssmtp/ssmtp.conf: [Errno 2]`** |

★★ **根因**：`notify-spool.sh` 靠 **DSM 自己的 SMTP 配置**发信（真路径 `/usr/syno/etc/synosmtp.conf`，`ERR-DSM-04`）——
**那个文件只在宿主机上，容器里没有**（镜像没带、也没挂）。★ **这不是配置漏了，是"搬进容器必然如此"**。
★ **"挂进去"这个补救也不划算**：等于把**邮箱口令再多暴露给一个容器**，而全部收益只是"换个地方执行同一条命令"
（`ERR-DOCKER-10` 原文判定：**「权衡不划算」**）。
⇒ 更关键：本项目通知系统的**全部设计理由**就是"**凭据只留在 DSM 里，从不外流**"
（`notify.py` 头注：*本文件没有一行凭据*）—— 为省一条任务把口令摊给容器，**正好把设计目的反掉**。

★★ **而且它压根不是"重复路"，是分工**（`ERR-SCHED-08`）：
```
drive-loop.py ──写事件──▶ spool/*.txt ──排空+发信──▶ archive/ + log/<日>.tsv ──▶ 邮件
   (生成, 容器里)            (中间站)      (出口, ★ 必须在宿主机!)
```
* 容器侧（`drive-loop.py`）**只负责写 spool**（其注释：「发信由 NAS 上的 `notify-spool.sh` 读 DSM 自己的 SMTP 配置完成」）；
* **发信只有 `notify-spool.sh` 做，而它搬不动**；`--digest` 属**发信那半边** ⇒ **天生属于容器外**。
* ★ 容器就算"到点了"也**还得回来叫宿主机发**，而 DSM 上**没有干净通路**（没 SSH = `ERR-DSM-09`；
  容器→宿主机 LAN IP = **hairpin NAT ✗**，`ERR-NET-01`）⇒ **绕一圈回原点，还多一个必须挂口令的容器。**

★★★ **由此得到一条可分界线（本轮唯一的"新知识"）**：
> **"哪条该搬容器、哪条不该" = 它碰不碰 DSM 的 SMTP 配置。**
* `reseed-drive-loop`（跑批）**该停、该由容器取代** —— **不含凭据**，搬进容器是纯收益（已停，`§26.5.2`）；
* `reseed-notify-drain` / `--digest`（发信）**不能搬** —— 碰 DSM 的 SMTP，**保持容器外**。
★ 这与 `§26.5.2`「`notice` 定案：**不搬，保持启用**」**结论一致**，本轮只是**补上了"为什么不能搬"的实物依据**。

### 一、前半句「每个种子只要搜到了就不再搜」⇒ ✅ **已实现，而且是结构性的**

| 位置 | 事实 |

| `state.py:1634` `todo()` | 只排除 `DONE_STAGES` ⇒ 这两档**永不**进待搜 |

⇒ 到了这两个 stage，**无论池怎么排、周期怎么算、有没有新站**，都**永不**再进待搜。

### 二、后半句「一个站搜到，其他站也不用搜」⇒ ✅ **结果成立，但机制是"整部退出"，不是"逐站跳过"**

★★ **关键事实**（`drive-loop.py:422` 的 `check_indexers()` docstring 里写着，我核过源码）：

> cross-seed 按它自己的 `TORZNAB_URLS` **全站搜索**；
> `--indexers` 只决定状态机把"搜过"**记到哪个站名下**（`indexer_seen` / 重搜周期）。

实测证据链（三处对齐）：

1. `state.py:2656 post_webhook()` 一次只 POST **一个 `path`**：`body = urlencode({"path": path})`
   —— **body 里没有 indexer 字段**，我们**根本没能力**"只让某个站搜"。
2. `state.py:2684 drive_webhook()` 按**部**发（不是按站发）⇒ **请求数 = 部数**。
3. cross-seed 收到一次 webhook ⇒ 拿这个目录名去它配的**每个站**各搜一遍。

⇒ 于是后半句**自动成立**，靠的是**①那条规则**：

- **A 站搜到** ⇒ cross-seed 找到单种 ⇒ 注入 qB ⇒ 这部片进 `SEEDING`/`MATCHED`
  ⇒ **整部退出待搜**（`DONE_STAGES`）⇒ **B/C/D 站自然也不再搜了** ✅
- **四站都没搜到** ⇒ 记 `UNMATCHED`，`indexer_seen` 按预算记一笔/几笔
  ⇒ 各站**按各自周期**到期（这是 `due_indexers` 的活）

★ **所以"一站搜到就全停"是成立的，但靠的是"整部退出"，不是"逐站跳过"** ——
两者**结果**相同、**机制**完全不同。★ 这也解释了 `due_indexers` 的语义：
它回答的是「**这部片该在哪些站重搜**」（**记账口径**），
**不是**「这次该发几个请求」（**永远是 1 个**）。

### 三、★★ 一个必须和 `§26.34` 二**合起来看**的推论（分开看会以为两条结论打架）

既然**一次 webhook = 全站搜**，那么 `#6③` 的"首次探索预算"压的**不是请求数**
（请求数由**部数**决定），而是**记账口径** —— 即"这部片**算不算**又到该搜的周期了"。

⇒ 这与 `§26.34` 二那条发现（**"预算只减站数、不减部数"**）是**同一件事的两面**：

| 说法 | 说的是 |

### 一、`deploy.sh` 的闸门：从「只看目录在不在」改成「**真的去读一次**」（`cb5b6f1`）

**事故现场**（用户 2026-09-21 亲历，见 `§26.35` 前后的排查）：
```
mkdir: cannot create directory '//192.168.0.7/docker_ssd': Permission denied
```
★ 而**在此之前**它已经打了「有差异的文件 (**29**)」、**29 条全是 `[新]`** ——
读起来像"首次部署一次到位"，**根本看不出是坏的**。直到 `mkdir` 才炸。
⇒ **这正是本项目最忌的形状**：「**判据看着过了、其实没测到东西**」。

**根因**（★ **当场断开共享实测**，不是推理 —— 这才是本节最该记的方法）：

| 判据 | 凭据错时 | |
|---|---|---|
| `[[ -d "$DST" ]]` | **true** | ★ **放过（缺陷）** |
| `ls "$DST" >/dev/null 2>&1` | **false** | ✅ 拦住 |
| `[[ -f "$DST/orchestrator/main.py" ]]` | **false** | ✅ 拦住 |

⇒ `-d` 走 `stat()`，MSYS 对 UNC 路径**不真正展开目录内容**；而 `ls`/`-f` **真的去读**
⇒ 凭据错就被拒。**取 `ls`**（不挑文件，白名单增删都不影响它）。

**两处都改了**（只改一处不够 —— 这是本节第二件要记的事）：
1. **第一道闸**：`-d` → `ls`，报错里带"怎么修"的指引；
2. **`[新]` 有两种含义被印成同一种**：真·新文件 vs **读不到**（凭据错时 `[ -f ]` 也一律为假）
   ⇒ 加**指纹判据**：**全 `[新]` 且总数 > 3 且目录读不出内容** ⇒ 报警并 `exit 1`。

★★★ **一条只能实测发现的边界，必须留在注释里**：
> **断开后头几秒三种判据全都放过** —— Windows 会**缓存** SMB 会话（连接是懒惰建立的）。
⇒ 这一闸**不是瞬时的**，挡的是"**缓存过期后**"的坏状态。
⇒ **推之前先跑 `--dry-run` 看差异数**（大片 `[新]` = 假的）这条习惯**仍然必要**。

**新增回归测试** `tests/test_deploy_gate.py`（9 条，离线，`35/1287` 中）：
判据**分三重**，缺一都不够 —— ① 源码级（`-d "$DST"` 那种写法必须绝迹）
② 行为级好路径（正常目录**不许误拦**；只测坏路径 = 把闸门做成永远红）
③ 行为级坏路径（列不出内容的 DST ⇒ **非零退出**）。
★ ③ 在造不出该条件的平台（root / Windows 忽略权限位）**如实报"未验"**，不静默跳过。

★★ **这个测试自己踩了两次「判据看着过了、其实没测到东西」** —— 都靠**变异测试**抓出来：
| 我写的判据 | 为什么没测到东西 | 修法 |
|---|---|---|
| 抓 `-d` 的正则写成**单括号** `[ -d ]` | 真代码是 `[[ ! -d ]]` ⇒ **变异时不红** | 改 `\[\[? ... \]\]?` + 可选 `!`，**当场用变异复验**（红条 1→2） |
| 指纹判据只钉字符串 `N_NEW` 在不在 | 删掉自增语句**照样绿** | 改钉 `N_NEW=$((N_NEW+1))` 必须在 + **当场复验**（红条 0→1） |

★★ **变异验证（实测，红条数是当场跑出来的）**：4 个变异全部按要求变红 ——
① 闸门改回 `-d` ⇒ 红 **2**（含主判据）；② 删 `N_NEW` 自增 ⇒ 红 **1**；
③ `echo` 里塞反引号 ⇒ 红 **1**；④ 去掉「总数 > 3」 ⇒ 红 **1**。

★ **一个我自己造的 bug，记下来**：报错文案里我用了**反引号**包 `-d` / `ls`，
shell 把 `ls` 当**命令替换真的执行了**（打印出目录列表）—— **报错文案本身成了 bug**。
现已修，并加了一条判据（`echo` 行里不许有反引号）钉住。

**(1) 容器名错了 —— 是 `reseed-drive-loop`，不是 `drive-loop`。**


**(2) ★★ 真正的原因**不是「它是 `sh` 读的脚本」—— 而是「**它改的是 argv**」。

> **推完不重启 = 那个进程永远读不到 `--pool`**，而 `deploy.sh` 的分类**看不出这点**
> （它只知道"这文件是挂载的、不用 build"，**不知道有人已经把它读进内存了**）。
