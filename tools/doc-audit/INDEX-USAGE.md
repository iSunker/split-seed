## 一、这是什么

**被审的文档**（`README` / `SUMMARY` / `summary/` / `ENVIRONMENT`）**太大**，检索靠人眼。
> ★ **文档分工 / 优先级：见 `CLAUDE.md` 的真源表**（唯一完整版 —— 这里不复述）。
> ★ **本文自己这一侧**：本文**不是事实源**，只讲**这些投影怎么用** + **某一天量到的读数**。
> ★ **对本文件的影响**：`01`/`02`/`03` 的 `DOCS` **不变**（仍扫仓库根 `*.md` + `summary/*.md`），
> 所以 README 变小**不会**让投影失灵 —— 但**读投影时要按新口径解释**：
> `README 标题` 那一列变小是**预期的**（搬家），不是"文档被砍了"。
> 依据：搬完实测 `悬空 / 半悬空 / 锚点无命中 / 锚点歧义` 全 **0**，LEGACY 守恒 **23**。

`tools/doc-audit/` 干的事不是拆文档，是**给它们做投影**：

> ★ **2026-09-16 起，`SUMMARY.md` 的正文按章拆到了 `summary/`**（入口只留导航 + §N→文件 表；
> 拆法见 `tools/split-summary.py`，**纯字节切分、正文一字未改**）。
> **事实源没变也没多** —— 只是同一批字节分开装。但**投影的输入集合从 3 个文件变成 28 个**，
> 于是三个脚本统一改走 `mdwalk.doc_files()`，不再各自 `glob("*.md")`：
> 只扫顶层会让 25 章的标题从结构树里**静默消失**，并让**全部 §N 引用**（约 690 条）**全被判成悬空**。
>
> ★ **分章不是投影** —— 别混这两件事：投影是**派生数据**（可再生成、会漂、不进 git）；
> 分章是**同一批字节换了存放位置**（进 git、是事实源本身）。两者方向相反。

```
        ┌─ 事实源（唯一）────────────────────────────────────┐
        │  ENVIRONMENT.md  ★2026-09-20 起含运维事实           │
        │  README.md       ★2026-09-20 起是门面，不再是事实源  │
        │  SUMMARY.md（入口）+ summary/00..24-*.md（正文 25 章）│
        └───────────────────┬────────────────────────────────┘
                            │  只读，可反复跑（口径统一在 doc_files()）
        ┌───────────────────┴────────────────────────────────┐
        │  01_headings  → out/headings.tsv   结构树           │
        │  02_refs      → out/refs.tsv       引用表           │
        │  03_terms     → out/terms.tsv      倒排表           │
        │  04_probes    → out/probes.tsv     事实表           │
        │  05_linerefs  → out/linerefs.tsv   行号引用表 ★新增  │
        └────────────────────────────────────────────────────┘
```

**投影只读事实源，事实源不读投影。** 这条方向不能反过来 —— 一旦反了就成了环，两边都会漂。

★ **2026-09-20：从四份变五份。** `05_linerefs` 补的是**位置级**引用（`file.py:123`）这一族 ——
前四份管的都是**符号级**锚点，接不住它。★ 它与 `02_refs` 的分工不是"多查一类"，
而是**判据本质不同**：符号不会漂、行号会漂（见下面第二节 `05` 那格）。

`out/` 与 `out.baseline-*/` 都在 `.gitignore` 里，但**理由不同**：
`out/` 是**可反复生成的派生数据**，冻进仓库只会变成一条会漂的"事实"；
`out.baseline-*/` 是**一次测量的快照**，进 git 就会从"某天的读数"升级成"事实源"。
两种都不该进 —— **除非 09-20 决定要长期保留那份基线**（那时才另说）。

★★ **`06` 为什么是第六份、而且它不是"投影"**：前五份都只读**结构/引用/读数**，
**没有一份管"这句话和那句话是不是同一件事、谁先谁后"**。
`06` 补的正是这个 —— 它是**第一条"给规矩装执行者"**的判据（见下）。

★★★ **`06` 的立此现场（这条比脚本本身重要）**：
用户的判断是「**每次用 AI 的税很高，想减少重复交代**」。查下来**税不在"投影多"**，而在

却发生在本节自己身上**」。
⇒ **`06` 就是那个执行者**：以后「真源分家」由闸门喊，不由人记。

★ **`06` 的分界线（★ 判据的核心，别记反）**：不是"有没有划掉段"，而是
**"这份文档是给人查事实的，还是给人看过程的？"**

| 文档 | 允许"先错后对"吗 | 为什么 |
|---|---|---|
| `ENVIRONMENT.md` / `README.md` / `INDEX-USAGE.md` / `CLAUDE.md` | ❌ **不许** | 读者**只读一处就去做事** ⇒ 改了就把**原句改成对的**（旧值进 git 历史）|
| `summary/` | ✅ **允许** | 过程记录，`A.11` 第 7 条**故意**要 `~~原句~~ + 更正`（`§26.16`「过程记录里的话不追改」）|

★ 实测依据（2026-09-20）：把 `ENVIRONMENT.md` 的 14 处划掉逐条看过 —— 只有 **3 处**是
"读者先撞上错的"（都在**开头/角色定义**），其余 11 处是**证据**（对的结论在前）。
⇒ 若不设这条豁免，闸门会**永远红**，而「**永远红的闸门 = 没人看的闸门**」。

ⓘ **`06` 自己栽过两次，都由"阴性对照"抓出来（★ 这正是它值得信的原因）**：
1. **B 类第一版漏报**：`~~错句~~` **单行自闭合**、下一行就是更正 ⇒ 被
   `NEAR_LINES`（离得近就不报）**放过** —— 而那恰恰是**最该报**的形状。
   ⇒ 改为：`a == b`（单行自闭合）**永远报**，只有**跨行**段才用距离豁免。
2. **A 类第一版永不触发**：键取"前 24 字符"，而两次更正**恰恰在那一截里不同**
   ⇒ 拿"变了的那部分"当身份。⇒ 改为：**剔掉数字/值** + **前缀包含即算同一事实**。
★ 两次都验证了：**不做阴性对照，根本发现不了**（改完"跑一次绿的"看着完全正常）。


★★ **`05` 为什么是第五份、而不是并进 `02_refs`**：`02_refs` 的六族锚点全是**符号级**的
（`§N` / `ERR-XX-NN` / `「标题」`）—— **符号不漂**。而 `file.py:123` 是**位置级**的，

### ★★ 与投影并列的第三种东西：**生成器**（`tests/gen-counts.py`，2026-09-20 新增）

投影是**从事实源派生读数给人看**；生成器是**从机械真值派生数字写回文档**。方向不同：

| | 投影（`01`–`05`） | 生成器（`tests/gen-counts.py`） |
|---|---|---|
| 输入 | 事实源（md） | **真跑**测试、数 stdout 的断言行 |
| 输出 | `out/*.tsv`（**不进 git**） | `tests/COUNTS.json` + `tests/README.md` 生成区（**进 git**）|
| 谁读 | 人 | 人 + `test_readme_counts.py` |
| 判据 | 悬空 / 越界 = 0 | `--check` 退出码：源与展示一致 |

★★ **它存在的理由是"停收重建税"**（用户 2026-09-20 的判断）：同一个数原先在
**两处手写**（日期行 + 表格每格），每加一条断言要手工改两处，忘了就漂
（实测漂过 `1104 → 1124`；`test_once_gate.py` 32→41 那次**两处一起漂、相互抵消、
检查照样绿**）。⇒ 把「数」降级成**派生数据**后，**「三处联动」变成「跑一次生成器」**。

★★★ **一条必须记住的设计约束**（第一版就栽了）：**断言是运行时 `print` 出来的，
源码里没有** ⇒ 「扫描源码来数断言」**不成立** —— 第一版把 28 个脚本数成 **1 条断言**
（只数到 `test_readme_counts.py` 里那句正则字面量自己），而**屏幕上那个数看着完全正常**。
⇒ 必须**真跑**。代价约 **40 秒**，但那是**机器的时间**。

★★ **第二条**：注解（表格第 3 列「钉住什么」）是**人写的**，它的真源是 `COUNTS.json`
（**不是** README —— README 只是它的渲染结果）。第一版拿 README 当真源 ⇒
**跑第二遍生成器就把 28 条注解全换成占位符**。⇒ 判据：**渲染结果不能反过来当真源**。

> ★★ **踩过的坑（写下来免得下次再踩）**：本机 Python 的 `Path.write_text()` 默认**写 CRLF**，
> 而本仓 `.gitattributes` 是 `* text=auto eol=lf` ⇒ 用它改 `README.md` 之后
> `git diff` 会把**整份文件**显示成改动（"每行都变了"），把真实的 1300 行改动淹没。
> ⇒ 写仓库文件的脚本一律用 `open(..., newline=chr(10))`（本目录的 `apply-*.py` 里
> 有个 `_write_lf()` 就是干这个）。★ 同 `SUMMARY §28` 与 `.gitattributes` 注释里那条。

★★ **`05` 刻意只报两件铁定的事**（① 目标文件不存在 ② 行号 > 文件总行数），
**刻意不判**"行号还指不指得对那一行" —— 那个判据**必然假红**（内容随时改，
而"内容变了"≠"引用坏了"）。⇒ **位置级引用的正确归宿是换成符号引用**，
`05` 只负责**把已经烂掉的抓出来**，不假装能维护它们。
★ 实测（2026-09-20）：101 条引用里 **1 条**铁定失效
（`summary/30` 引 `README.md:1856`，而 README 只有 1787 行 —— `f2c2af9` 瘦身的产物）。

★ **`05` 自己栽过一次假警报，记下来**：第一版只按"仓库里有没有这个文件名"判 ⇒
`run-resident.sh` 被引 3 次、仓库里找不到 ⇒ 报 3 条 `NO-FILE`。而它**是**合法的 ——
`deploy.sh`（现由 `DEPLOY_MANIFEST` 承担）曾把 `scripts/drive-loop-resident.sh` 部署成
**`drive-loop/run-resident.sh`**（**改了名**）。
⇒ 补 `DEPLOY_ALIASES` 两跳解析（先按名找，找不到再按 NAS 部署名反查）。
★ **教训**：这族的判据**不能只看"仓库里有没有"** —— 同 `B.10` 第 1 条
（「某台机器上没有」≠「环境里都没有」），方向反过来也一样。
★ **阴性对照**：注入 `drive-loop.py:999999` + `nonexistent-thing.py:5` ⇒ 两条都抓到；
恢复 ⇒ 回到 1 条。

### ★★★ 第四种东西：**读数** —— 它**不能**降级成派生数据（2026-09-20 立）

> 起因：用户问「把 `ENVIRONMENT.md` 的读数也按 `tests/gen-counts.py` 那条线降级成派生数据」。
> **查下来答案是"不能"，而且理由是可判的。** 这一节把这个分界写死，免得下次再问一遍。

**判据只有一条：这个数能不能"重算出来"？**

| | `tests/` 的断言条数 | `ENVIRONMENT.md` 的读数（`605 部` / `475 条` / 磁盘水位）|
|---|---|---|
| 重算 | **能** —— 再跑一遍测试，数 stdout | **不能** —— 那是**某时刻观测到的世界** |
| 跑两次 | **逐字节相同** | **每次不同**（水位在动、种子在增减）|
| 当"源 → 派生" | ✅ 成立 | ❌ **不成立** |

★★ **为什么硬套会制造一个更隐蔽的漂**：`ENVIRONMENT.md` 自己把这条写死了 ——
「**`/volume1` 的"可用"读数不是常量**……量级从 **0 到 5.3 TiB 都出现过**」。
把一个**会动的数**生成进正文 ⇒ 生成器每跑一次，就把"**曾观测到**"重新盖章成"**现在就是**"，
而正文里那份「2026-09-17 更正」的说明会和它**自相矛盾**。
⇒ 这不是消税，是**把显性的漂换成隐性的漂**。

★ **而且没有"税"可收**：`tests/` 那次的病灶是**同一个数在 3 处手写**。
实测 `ENVIRONMENT.md` 的读数**在 README / SUMMARY 里各为 0 次**
（`605`→2 次、`475/475`→1 次、`5.33 TiB`→6 次，**全在文件内部**，
是同一件事的正文 + 更正 + 口径对照表）⇒ **没有第二份要同步** ⇒ 省不掉任何动作。

⇒ **正确处置 = 扩探针**，让「**文档声称 vs 生产实读**」当场可判（见下一小节）。
这正好兑现了 `ENVIRONMENT.md` 自己那句：「凡能一条命令读出来的，就别信写死的
—— 每次用之前回读一次」。

#### 扩探针（2026-09-20：5 条 → **8 条**）

补的正是原先的**覆盖缺口** —— `A.19.1.1` 那三句的判据此前**根本不存在**：

| 新探针 | 对应文档声称 | 实读结果（2026-09-20）|
|---|---|---|
| 状态机总部数 | `A.19.1.1`「`state.db` ✅ **605 部**」| **605** ✅ 对上 |
| 农场条数 | `A.19.1.1`「`reseed_farm` ✅ **475/475**」| **475 = 474 目录 + 1 散文件** ✅ 对上 |
| qB 本项目种子数 | `A.19.1.1`「qB :3060 的 **509/509**」| **930**（**不是** 509，见下）|

★★★ **三条踩坑记录 —— 两次错在"口径"，一次错在"读不到"的判法**：

1. **农场：我把"475"数成了 474。** 第一版用 `if p.is_dir()` ⇒ 漏掉那个**散文件**，
   读回 **474**，**看起来像文档过时了**。真口径在 `summary/10` 那张表里写着：
   「直接子项合计 = **475**（**474 目录 + 1 个散文件**）」⇒ 该用 `os.listdir` 语义。
   ★ 这就是 `B.10` 第 14 条那个形状：**数出来的数看着完全正常，但答的不是同一个问题**。

## 六、安全纪律（改这些脚本时**必须守住**）

**两条都要有，缺一条就是漏洞：**

1. **不选可能含凭据的列。**
   `cross-seed.db` 的 `indexer.url` **每条都带 `apikey=<Prowlarr 应用级 key>`**，
   那个 key 能开 Prowlarr 上**所有 PT 站**。判「哪个站、什么状态」靠 `id` / `name` / `status` 就够，
   `url` 对判读**零价值**。**能不取就不取** —— 这是主防线。

2. **出口统一过 `redact()`。**
   万一某个探针必须碰这类列，或异常信息里带出来，在**打印和落盘之前**按**值的形状**抹掉。
   按**键名**匹配会漏掉嵌在 `options` / `fields` / 异常文本里的凭据 ⇒ 兜底要按形状。

> 判据是「**只读 + 不回显凭据 + 只打聚合**」这三条同时成立 ——
> 与 `check-deploy-drift.py` 里 `qb-census` / `linkguard` 那两条**同一个形状**。
> 不是「它碰没碰凭据」—— 后者会把所有有用的诊断工具都挡在门外。

另外：**探针一律只读**。库用 `query_only`，UNC 直读、**不 `cp` 副本**（WAL 里未 checkpoint 的数据会丢）。

### ★★ 冻早了一步 —— 坑 · 规矩 · 判据（**三件是一条链**）

它们不是三条并列的教训，是**同一条的三个位置**。

★ 这条链还有**一个同族的姊妹**（错在**版本轴**上，而不是时间轴上）：
见下面「**姊妹坑：拿错了参照版本**」。**两条要一起看**，否则会把其中一条当成孤例。

#### ① 坑：快照冻在「落定之前」

**发生过的**：09-13 第一次冻基线时，当天的文档改动（`Task#86` 去掉那个自指括号）
**还没做**就先把 `out/` 拷成了快照。万幸那次改动只少一条引用、
而 `refs.tsv` 恰好已经在改动后重跑过，才没出事 —— **是运气，不是设计**。

**它为什么比「hash 每跑必变」更危险**：
基线一旦冻错，**两周后所有比对都是在错的参照系上做的，而比对结果看起来完全正常** ——
「变了 3 处」的真实含义可能是「**基线错了一处 + 今天正常变了两处**」，
这两件事**在输出上分不开**。

**它属于哪一族**：这是**时间窗问题**，不是判据对不对的问题。
与「**部署要等批次间隙**」（`SUMMARY` §18.19.4.1）**同一族** ——
区别只是：那条动的是**生产**，这条动的是**基线自己的可信度**。

**动作**：任何「冻结快照」之前，先问一句 ——

> **被冻的东西，还是不是最终态？**

#### ② 规矩：冻结是「**当天最后一个动作**」

这**不是新知识** —— 它是①的**正面表述**：坑是"你会冻早"，
规矩就是"**冻在今天所有改动落定之后**"。

**09-13 实测**：这天基线**冻了 3 次** —— 前两次都是冻在改动之前
（一次是 `Task#86` 去掉那个自指括号，一次是 `B.10` 第 14 条），
**两次都是下面这条自检抓出来的**。

#### ③ 判据：落定后，**再跑一次**投影，两次 `sha256` 必须相同

冻完**立刻**再跑一遍投影，比对两次的 hash：

```bash
cd tools/doc-audit
```

**相同 ⇒「落定」了。不同 ⇒ 还有东西在改文档**（或哪个脚本有不确定输出）——
**先查清再冻**，别把"没落定"冻成基线。

> ⚠ **`probes.tsv` 必须排除在这条自检之外** —— 它天然每次都不同
> （`retry_after` 在倒数、卷水位在动、批次会写 `timestamp`）。
> 对它用不了"两次相同"，只能用第三节那张**四列表**去判。
> ★ 这一步排除是**必须**的：不排除，这条自检就**每次都报警** ——
> 而「**一个会误报的哨兵，两次之后就没人看了**」。

> **09-13 实测**：写完本节后立刻重跑三份，`headings` / `refs` / `terms` 的 hash
> 与冻结基线**逐个相同** ⇒ **落定**。
> 顺带验掉一件不该靠"应该"的事：**编辑 `tools/` 下的 md 不会动投影** ——
> 因为 `DOCS` 只扫仓库根（第三节那条硬限制）。这条以前只是"推理应该如此"，
> 现在是**实测**。

### ★ 姊妹坑：**拿错了参照版本** —— 「我以为我拿的是 A，其实拿到的是 B」

> ★ 与上面那条链**同族的另一面**：那条错在**时间轴**，这条错在**版本轴**。
> **两条要一起看**，否则会把其中一条当成孤例。

**发生过的**：查证"三份 hash 为什么全红了"时，用 `git show HEAD:ENVIRONMENT.md`
取「改动前的版本」去做对照 —— **可 `HEAD` 已经包含那次改动了**（我在查证**之前**就把它提交了）。
于是比的是「**新版 vs 新版**」，结论是「**完全一致**」，**差一点就被当成"其实没变"写进文档**。
改用 `HEAD~1` 才拿到真正的前置版本。

**与那条链的对照**：

| | ① 冻早了一步 | 本条：拿错了版本 |
|---|---|---|
| 参照系错在哪 | **时点** —— 改动还没落定就冻了 | **版本** —— `HEAD` 已含这次改动 |
| 结果 | 基线**自出生就是错的** | 「新版 vs 新版」⇒ 假结论「**完全一致**」 |
| 屏幕表现 | 看起来完全正常 | 看起来是**干净对比** |

**本质是同一件事**：**我以为我拿的是 A，其实拿到的是 B。**
区别只在错在**时间轴**上，还是错在**版本轴**上。

**动作**：任何"拿旧版来对照"的动作，先**回读你实际拿到了什么**——

```bash
git show <rev>:ENVIRONMENT.md | grep -n '<这次改动的特征串>'
# 命中了 ⇒ 说明你拿的**不是**旧版，换个 rev
```

★ 与 `A.10` 那条 ★ 同源：**别信你以为的，回读实际的。**

### ★ hash 变了 **≠** 结构变了（三份表**都嵌行号**）

**发生过的**：09-13 给 `ENVIRONMENT.md` 加了一行表格 + 一段注，三份 hash **一起红了** ——
第一反应是"结构被改了"。逐条比对后才知道：**红的理由不是同一个** ——
`headings` / `terms` 只是**行号列在动**，而 `refs` 是**真变了**（+3 条真引用）。
★★ **三份全红、两个原因，而光看 hash 分不出哪个是哪个。**

**它属于哪一族**：`ENVIRONMENT` `B.10` 第 14 条 ——
**输出本身不承载判据**（空集像"没事"、非空集像"有事"，这两个方向都能骗人 —— 第 14 条另补了第三个「措辞把结论写死」）。

**处置**：见**第三节**（两层比对 + `CONTENT.sha256`）。
★ 并注意它与 `probes.tsv` 那条**处置像、理由不同**（那条是**读数**，这条是**元数据**），
**别写成同一条** —— 第三节末尾有对照表。

### ★ 空转的提交/推送：一个「返回 1 被我丢了」，一个「返回 0 骗了我」

**发生过的**：09-13 漏了 `git add` 就 `git commit` —— 那次提交是**空转**，什么都没提交；
紧接着的 `git push` 打印 `Everything up-to-date`，**看起来正像"已经推了"**。

**两条命令的返回值不一样，必须分开说**（09-13 实测，不是推断）：

| 命令 | 空转时返回 | 输出 | 谁在骗人 |
|---|---|---|---|
| `git commit`（暂存区空） | **1** | `nothing to commit, working tree clean` | **没骗人** —— 是我**没接 `&&`、也没读它**，把判决丢了 |
| `git push`（已在最新） | **0** | `Everything up-to-date` | ★ **真的会骗人** —— 0 是"成功"，事实是**什么都没推** |

**它属于哪一族**：与 `SUMMARY` §18.17.3「**绿了但规则没参与**」同源 ——
动作发生了、看起来成功了，但**那件事本身没发生**。

**两条护栏**：

```bash
# ① commit 前：暂存区为空就别 commit（实测：空时 rc=0 ⇒ 护栏成立）
git diff --cached --quiet && { echo "★ 暂存区为空，别 commit"; exit 1; }

# ② push 后：读回真实状态，别信返回值 —— HEAD 与 origin/main 的 hash 骗不了
git rev-parse HEAD origin/main   # 两个 hash 必须相等
```

★ **第二条是关键**：`commit` 的失败还能靠 `&&` 串出来，
**`push` 的失败串不出来 —— 它返回 0**。所以推完必须**读一次真实状态**
（就是 `A.10` 那条 ★：**别信调用的返回值，读回真实状态**）。

### ★★ 给人抄的命令，必须**先跑一遍或对照签名** —— 与「我记得写过了」同族

**发生过的**（2026-09-14）：给下面第八节的「动作」那一格写探针命令时，
`--id 1` 是**凭记忆**写的 —— 而 `scripts/torznab-probe.py` 的位置参数 `q` 是**必需**的
（脚本头部：`python scripts/torznab-probe.py "<原样 q>" [season] [--id N]`），
`--id` 反而**默认就是 1**。照着敲会**直接因缺参跑不起来**。

**它属于哪一族**：与另外两条**同族**，共同点是 **记忆 vs 事实**：

- 「**我记得写过了**」≠ 文档里真有 —— ★ 这条的**活标本就是本文档自己**：
  那张「使用记录」表（第三节末尾）曾被描述过（"观察记录表 · 不可重跑（行为）"），
  而**全仓库 `grep` 0 命中** —— 连 `SUMMARY` 里都没有 `doc-audit` 的踪迹。
  不是"指错了地方"，是**这一样压根没建**，而它正是两周观察的**唯一使用面**。
- `git show HEAD:` 拿错版本 —— **参照系错**。

★ **但它有一个不一样的地方，值得单独说**：

> **这条命令是「给人照着敲的」。**

同 `SUMMARY` §20.8（**告警正文里的查证命令必须自带脱敏**）—— 那里是**命令内容危险**，
这里是**命令不完整**。两者是同一母题的**两个面**：

> **给人抄的命令，必须先自己跑一遍、或对照签名。**

门槛比"给自己用的命令"**更高** —— 因为**读者没有上下文去判断这行缺了什么**。

**动作**：往文档 / 告警正文里写命令之前，先打开**被调脚本的签名或 `--help`** 看一眼，别凭记忆。

**判据**：命令块里的每个参数，都能在**被调脚本里**指出它的名字、以及它是不是必需。

★ 另**不建 `ERR-*` 条目**：它不够"环境错误"，是**文档纪律** —— 与本节这几条同档。

### ★★ 搬迁（"同一批字节换个地方装"）的验证法（2026-09-20 立，README 拆分那次）

**形状**：把一大段正文从 A 文件搬到 B 文件。它**不是编辑、也不是删除** ——
但**看起来像**"改了许多字"，所以最容易的错法就是**顺手改一点**，而改过之后
**下一个读者看不出这里改过**（同 `A.11` 的反例）。

**判据只能是"逐字节"**，不是"我看起来搬对了"：

```bash
# 搬迁前：记住每一段的正文指纹（只比正文，**标题的编号前缀允许变**）
python tools/doc-audit/verify-move.py --save man.json \
    --from <搬迁前的 rev>:README.md --seg "<该段的标题子串>"

# 搬迁后：逐段证明它在新文件里逐字节相同
python tools/doc-audit/verify-move.py --check 1 --manifest man.json --into ENVIRONMENT.md
```

★ **口径（别改）**：剥掉标题行里的**编号前缀**（`### 原理 A` → `### A.15.1 原理 A` 是搬迁必需的），
**除标题那一行以外一个字都不许动**。比对时会**打印差异** —— **不静默跳过**。

★★ **这次实测踩到的三个坑，都是"工具比人可靠"的实例**：

| 坑 | 屏幕表现 | 真判据抓住它的方式 |
|---|---|---|
| **段末多带了原文的 `---` 分隔线** | 完全正常 | `body_sha` 不相同 ⇒ 逐行 diff 出来是 `+''` `+'---'` |
| **块边界处吞掉了下一节的引言**（B 部分的「七格 schema」被算进上一段） | 完全正常 | 段长从 10 行变 15 行 |
| **内容本身对了，但块尾部多一行注释** | 完全正常 | 同上 |

⇒ **共同点：三样在屏幕上全都"看起来对"。** 这正是 `B.10` 第 14 条那句
**「输出本身不承载判据」** 在"搬迁"这件事上的形状 —— 唯一的判据是
**与搬迁前的字节比**，而**比之前要先回读你实际拿到了什么**（同下面那条
「拿错了参照版本」）。

★ **还有一条与它并列、但方向相反**：搬迁**会改引用面**。
本次搬走 6 个顶层标题 + 十几个子标题之后，`02_refs` **立刻报了 34 条 `ANCHOR-MISS`**
（`ENVIRONMENT.md` 里 `ERR-*` 条目的「怎么发现的」格还引着那些子标题）。
处置：在撤节指针处**保留原标题名**（含子标题），别为了"清爽"把标题改掉 ——
**标题名就是锚点**。

> ★ **反面**：不要为了让它变绿去放宽 `mdwalk` / `02_refs` 的匹配口径。
> 那是「**改判据去迁就数据**」，与 `B.10` 第 14 条同族。
